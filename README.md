# 七站双预测与单断面优化联合服务

本次源码更新增加实测合计与偏差。交付包以[新私有仓库的Release](https://github.com/zhangqian-1/jingneng-fluxcast-combined/releases)为准，仅在云端构建和容器验收通过后发布；没有对应Release就表示尚未完成封装。原r5安装包不包含本次功能，不能直接用于本版部署。新增字段见[实测合计与全天预测偏差](docs/实测合计与全天预测偏差.md)，本地记录见[本次修改与验证](docs/实测功能修改与验证-20260929.md)，构建方式见[云端封装说明](docs/云端封装说明.md)。

当前平台入口是 **POST `/api/v1/fluxcast/compute`**。按用户提供的第一份接口约定，请求只需原有的 `point_table`、`frames`、`renewable_data` 三个顶层字段；七个燃机场站和19个新能源场站一次提交、一次返回。完整契约见[平台接口说明](docs/platform-api.md)，本次结构与MD核对见[双预测与单时段优化](docs/双预测与单时段优化-20260926.md)。

96帧按用户确认解释为最近24小时历史实测，末帧是当前时刻。新版单点预测服务生成下一15分钟的1点，本服务使用该点，与同一时段的新能源可用预测一起求解一个时段，返回27个功率建议、同一目标时刻的totalPowerForecast及成本、碳排放两个指标。没有恢复旧8步滚动或96步联合优化。

原预测输出 `totalPowerForecast` 是七站合计发电功率预测，本模型将其作为等效供电目标。这不是独立用户侧负荷预测。系统提供调度建议，不自动下发控制命令。

新能源场站预测统一从平台请求的 `renewable_data` 读取。19场站预测接口的查询、批次选择与汇总由平台负责，算法不主动请求新能源接口，也不在缺数据时联网补取。`FORECAST_BASE_URL` 仅用于包内七站单点功率预测，与新能源取数无关。具体分工见[新能源数据来源确认](docs/新能源数据来源确认-20260927.md)。

价格编辑使用 `GET/PUT /api/v1/fluxcast/config/prices`，只包含七站发电成本和购电价共14项，不包含天然气价。保存需携带版本号，新价格只用于新建断面，历史与重试保持原版本；详见[价格接口约定](docs/价格参数配置接口约定-20260929.md)。

通过服务访问 `/dashboard/`，点击“编辑价格”读取并修改当前配置；“计算单价”仍显示历史试算采用的值。冲突或保存状态不明时必须重新读取核对，页面不会自动覆盖。直接双击离线HTML只能查看，不能保存服务价格。正式平台仍通过自己的鉴权后端转发同一路径，不能将未经鉴权的管理入口暴露到公网。页面验证见[价格页面验证记录](docs/价格页面验证-20260929.md)。

## 启动

完整离线交付包解压后，Windows运行 `powershell -NoProfile -File .\start.ps1`，Linux运行 `sh start.sh`。默认文档地址为 `http://127.0.0.1:18768/docs`，展示页为 `/dashboard/`。启动方式、镜像架构及持久化见[联合封装说明](deploy/forecast-dispatch/README.md)。

源码环境使用Python 3.10–3.11：

```sh
uv sync --all-groups --frozen
uv run uvicorn api:app --host 127.0.0.1 --port 8000
```

源码直接启动需配置 `FORECAST_BASE_URL` 和 `DAY_FORECAST_BASE_URL`。当前Dockerfile与Compose将单点预测、24小时预测和优化合为一个镜像、一个容器；两套预测只监听容器内127.0.0.1的8001/8002，仅公开8000一个端口。两套原预测代码、模型及依赖版本保留，缓存独立。升级旧三容器部署时按[部署说明](deploy/forecast-dispatch/README.md)保留数据卷并处理目录权限。

本版DAY_FORECAST_BASE_URL须连接由 `src/day_forecast_runtime.py` 启动的全天服务，不能只连接未增加内部history路径的旧服务。Docker启动器已配置该包装层。

全天曲线按北京时间自然日00:00—23:45（最后一点代表至24:00）保存，每天首次优化成功且候选可用时发布；没有08:30限制。缺少日界线候选时，会用零点前足够的真实历史在隔离缓存内自动补算；真实历史不足仍不拼接或造值。见[统一请求及每日发布契约](docs/统一请求与每日全天预测-20260929.md)。

## 当前接入规则

- `frames` 连续96帧，每15分钟一帧，按UTC解释；支持测点名称的点号转下划线。原预测模型需要的35测点见[清单](docs/forecast-measurement-points.csv)。
- `renewable_data` 直接接收19站合并的原始长表；严格选择 `timeSeries=1`，北京时间结束时刻减15分钟、转UTC后与下一目标时段对齐。
- 成功返回 `event_key`、`result_point` 与 `extra_info`。原30个下一时段数值结果、8个计划状态保持不变；新增当前末帧的实测合计和可计算的偏差，齐全时共32个数值点。当天首次发布曲线再加96点，齐全时共128点。实测质量状态也追加到extra_info。各点保留请求末帧的时间格式，但当前实测与下一时段调度的时刻不同；等待或错误时两个数组仍为空。
- 冷启动预测需要累计288个连续可用历史点；96帧是每次输入窗口，不等于模型完整初始化历史。未就绪返回202空结果。
- 约定没有额外运行状态字段，优化内部依据历史功率估计启停状态并留痕；不要求平台改传 `actual` 等嵌套结构，不虚构新能源实测值。
- 同一实际断面重试返回已保存结果；不同输入不得覆盖同一断面。输入过期、缺失、冲突或求解失败均不返回有效建议。

`/api/v1/fluxcast/single-period/compute` 仅保留为已弃用的r2调试兼容入口，平台不使用它。旧 `/compute` 与 `/api/v1/fluxcast/rolling/*` 已删除。预测初始化代理及状态查询是已有辅助接口，见[详细说明](docs/platform-api.md)。

## 代码与验证

`src/platform_adapter.py` 恢复原请求、字段与输出约定；`src/forecast_bridge.py` 调用原预测并对齐目标时刻；`src/single_period_*.py` 负责单步求解、时效、存储和状态约束。参数在 `config/`，求解器使用HiGHS，不需要Gurobi许可证。

```sh
uv run python scripts/check_delivery.py
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
```

原始业务文件通过哈希校验保护。容器验证和离线打包会核对实际镜像与源码哈希，不能用旧镜像的结果替代新代码验收。

`dashboard/` 及交付包独立HTML是固定历史情景展示，96点代表96次独立单时段试算，不是实时平台监控。原始数据、历史交付与历史报告保留；当前接口以本说明及第一份原始约定为准。

历史[20260929-r5](docs/交付下载-20260929-r5.md)是本次开发基线，不含新增实测返回及历史接收控制；不能用该安装包验证本次功能。新版须重新构建、通过容器验收后另行发布，不覆盖历史包。上传代码和安装包不代表生产已部署。ARM整包实机验证、康保实际容量及现场运行参数仍需现场确认。

## 两个预测功能的统一入口

| 功能 | 默认调用地址 | 用途 |
|---|---|---|
| 单点预测→单时段优化 | POST http://127.0.0.1:18768/api/v1/fluxcast/compute | 原三个字段；仅下一15分钟，返回30个优化结果点 |
| 当天0—24点预测 | 同一个 compute 请求 | 当天首次可发布时追加96个 totalPowerForecastDayAhead 点；后续保留已保存曲线 |
| 实测合计与同刻偏差 | 同一个 compute 请求 | 从原始末帧取19个功率值，返回totalPowerActual和可计算的totalPowerDeviation |

单点预测需要累计288点连续可用历史，长时段预测需要672点；两者每次都收96帧，原初始化代理同时预热两模型、缓存独立。优化只连接单点模型，长预测未就绪或停止不会改变优化的预测来源，也不会使优化变成长时段求解。两个预测量都是七站合计发电功率。详细接入见[双预测说明](docs/双预测与单时段优化-20260926.md)。

全天服务新增容器内history接收包装层，复用原预处理和缓存、不修改原模型文件。平时仅积累历史，不执行96点推理；北京时间23:45末帧到达时为次日生成一批。漏掉该时刻且当天候选缺失时，只用零点前历史补算；已有当天曲线不重算。首次发布也返回当前一点的实测和可计算偏差；若曲线是首次现算、生成时间不早于当前实测，extra_info附deviationBasis=initial_curve_comparison，不冒充提前发布预测的在线精度。例外不扩展到其他历史时刻，后续按原规则匹配已保存曲线。

当天曲线自动补算与平台缓存接入详见[说明](docs/当天曲线补算及平台缓存-20260929.md)。
