# 实测合计与全天预测偏差

## 调用方式

平台仍每15分钟调用一次 `POST /api/v1/fluxcast/compute`，默认端口18768。请求不增加字段，仍为 `point_table`、七站35个测点的连续96帧 `frames`、19个新能源场站的 `renewable_data`。无需另行调用实测接口。

输入示例仍使用 [platform-request.json](../examples/platform-request.json) 的结构。该文件是历史测试输入，不能直接发给生产服务；不要只改时间就把历史数值当作当前实测。

## 返回字段

原预测、调度数值和8个计划状态保留。仅HTTP 200的成功联合结果追加以下字段：

| 位置 | varname | 含义 |
|---|---|---|
| result_point | totalPowerActual | 请求末帧19个原始功率测点之和，MW；不含温湿度和新能源预测 |
| result_point | totalPowerDeviation | 已发布全天曲线的同刻预测减实测合计，MW；正值表示预测偏高，不是百分比 |
| extra_info | dataStatus | complete：19点有效；incomplete：部分缺测；missing：全部缺测 |
| extra_info | missingPoints | 缺测时的原始测点编码，逗号分隔 |
| extra_info | reason | 实测完整但不能返回全部数值的原因 |
| extra_info | deviationBasis | 仅首次现算曲线的当前点比较返回initial_curve_comparison；不是提前发布预测的在线精度成绩 |

每项仍为 `varname / timestamp / value`。result_point的value是有限浮点数，extra_info的value是字符串。可用数值全部齐全时，普通响应32个数值点；当天首次附带96点曲线时128个。不能固定按数组长度取值，应按varname与timestamp识别。

本次实测字段的timestamp等于请求末帧UTC时刻，保留空格/T、UTC后缀与小数位样式。例如末帧为UTC05:00，实测和偏差对应05:00；原单点预测和调度仍对应05:15。全天曲线包含当天各自的96个时刻。禁止把整个返回数组按同一个时间处理。

## 缺测与匹配

19个功率点齐全才返回合计；null、字段缺失、字符串、布尔值等无效值按缺测处理，不补0、不使用前值或部分和。真实0和有限负值保留。调度内部自身的修复规则不用于实测展示。

| 情况 | 新增数值 | 状态/原因 |
|---|---|---|
| 实测完整，有合格的同刻预测 | 实测合计、偏差 | dataStatus=complete |
| 当天首次发布补算曲线，当前实测完整 | 实测合计、偏差 | deviationBasis=initial_curve_comparison（生成时间不早于实测时刻时） |
| 实测完整，无合格的同刻预测 | 仅实测合计 | reason=no_matching_forecast |
| 任一功率测点缺失 | 不增加实测数值 | incomplete/missing、missingPoints |
| 合计或减法超出有限数值范围 | 省略不可用数值 | actual_out_of_range / deviation_out_of_range |

偏差只匹配页面使用的已发布自然日曲线，不读取单点预测或任意latest曲线。使用UTC时间点精确匹配，不加减8小时、不找最近点；日期归属沿用北京时间自然日。

一般使用在实测目标时刻之前生成并归档的曲线。当当天首次才补算曲线时，允许同时返回首次发布请求末帧这一点的偏差，附deviationBasis=initial_curve_comparison。此例外仅适用于内部recovery补算路径：历史截止北京时间前日23:45，排除当天实测，曲线批次与首次发布记录一致，并按同一UTC时刻匹配。不以模型实际生成时间较晚为由省略这一点，也不修改真实生成时间。

该例外只比较首次发布断面的当前一点，不补发当天全部历史实测，不回算其他早于生成时间的历史偏差。生成之后的新时刻继续使用同一曲线，正常返回偏差，不再附首次比较标记。旧数据库中无生成记录、来源不明或校验不通过的曲线不享受此例外；已保存的历史响应仍按原记录重放，不在升级时改写。

优化未就绪202、参数错误、断面过期或求解失败沿用原HTTP与空数组约定，不把实测可用伪装成调度成功。因此统一接口在调度失败时不会单独出实测；平台须处理这些状态。

## 每日预测与历史积累

完整96帧每次仍通过内部 `POST /api/v1/fluxcast/history` 写入全天模型自己的缓存；此路径不对平台公开，且不执行模型推理、不覆盖latest。转换仍是UTC输入、原模型北京时间特征、UTC预测输出，不改原权重与清洗规则。

北京时间23:45末帧到达、历史足够且次日曲线尚不存在时，调用原96点预测并持久保存。当天首次成功联合请求发布当天整批曲线，后续新断面只追加实测和偏差，不重复返回96点。原发布请求重试会重放96点。

数据齐全时，首次同时返回全天96点预测、未来15分钟预测、当前七站实测合计及同刻偏差，保留原调度结果。后续新时刻继续返回15分钟预测、当前实测及同刻偏差，不重复推理已有的当天曲线。

若缺少当天候选，沿用隔离缓存补算，只使用当天零点之前的真实历史；历史不足就等待。每个预测日期已有成功保存的曲线后不再推理；次日准备属于新的预测日期，失败可重试。首次部署仍须补足原模型要求的连续历史及天气上下文。

## 保存与部署

继续使用原三个持久化卷，无新增外部端口或容器。优化数据库新增 `day_forecast_provenance`（批次、实际归档时间、生成方式）和 `measured_power_result`（实测目标时刻、输入摘要、匹配批次与响应）。两套预测缓存仍相互隔离。

同一已成功发布断面的重试返回同一结果；输入变化不能覆盖原断面，沿用409冲突约定。晚到或更正数据也受原调度时效和不可变断面规则约束，不能按独立实测接口的补传规则直接使用。

升级前停止旧服务、备份三个卷；不得删除卷。新包装层启动方式已写入单容器启动器，需要重新构建联合镜像，单独替换GitHub源码或原镜像标签不会生效。原r5镜像不包含本次变更。本地测试通过不等于容器或现场已验收。

## 样例

[observations-output-fragment.json](../examples/observations-output-fragment.json) 是新增部分的完整JSON节选，不是完整联合响应。示例为19点各10 MW，实测190 MW、同刻预测1534 MW、偏差1344 MW；仅用于说明格式，不是模型实测成绩。正式响应还保留原30个数值及8个计划状态，可能另附当天96点。

[observations-initial-output-fragment.json](../examples/observations-initial-output-fragment.json) 展示首次现算曲线时的当前实测与偏差，增加deviationBasis标记。该文件也仅是响应节选，数值为格式示例；输入仍使用同一个platform-request.json结构，不增加请求字段。
