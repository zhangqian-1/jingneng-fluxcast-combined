# 云端封装说明

私有仓库：https://github.com/zhangqian-1/jingneng-fluxcast-combined

## 构建

在Actions选择Build and Verify Combined Delivery，点击Run workflow。构建在GitHub的Linux/amd64机器上完成，本机无需运行Docker。工作流只手动触发，不修改其他GitHub仓库或公司GitLab分支。

流程依次为源码检查和测试、校验并导入两份固定版本基础镜像、构建三合一镜像、真实模型联合调用、原模型文件与依赖核对、重建和故障恢复、镜像导出及交付启动脚本验证。首次现算的当前点偏差也纳入验收。新能源调度输入使用明确的测试情景，不等于现场闭环验收。

只有上述步骤全部成功，才在本仓库Release发布交付ZIP、SHA256校验文件和validation-evidence.zip。步骤失败时不发布交付包，在Actions日志中查看具体原因。本流程不依赖Actions大文件Artifact存储，交付文件直接进入私有Release。

## 交付

Release版本和镜像标签包含运行编号，避免新旧包混用。交付ZIP内有dispatch-image.tar.gz、start.ps1/start.sh、源码和联调记录；只需导入这一个联合镜像。使用说明见[部署文档](../deploy/forecast-dispatch/README.md)。

私有仓库及Release仅授权用户可下载，可以授予接收者访问权限，或另行转交下载后的ZIP和校验文件，不必将联合源码公开。部署服务器仍需Docker或兼容的Linux容器运行环境，并按约定补齐真实历史数据。

当前工作流生成Linux/amd64包，不是ARM64包。ARM部署须使用对应架构的基础镜像并另行构建验证。
