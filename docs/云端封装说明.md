# 云端封装说明

公开仓库：https://github.com/zhangqian-1/jingneng-fluxcast-combined

已验证交付包：[20260929-r36595586771a1](https://github.com/zhangqian-1/jingneng-fluxcast-combined/releases/tag/20260929-r36595586771a1)。源码、镜像ZIP及校验文件的下载入口见[README](../README.md#下载与交接)。

## 构建

在Actions选择Build and Verify Combined Delivery，点击Run workflow。构建在GitHub的Linux/amd64机器上完成，本机无需运行Docker。工作流只手动触发，不修改其他GitHub仓库或公司GitLab分支。

流程依次为源码检查和测试、校验并导入两份固定版本基础镜像、构建三合一镜像、真实模型联合调用、原模型文件与依赖核对、重建和故障恢复、镜像导出及交付启动脚本验证。首次现算的当前点偏差也纳入验收。新能源调度输入使用明确的测试情景，不等于现场闭环验收。

只有上述步骤全部成功，才在本仓库Release发布交付ZIP、SHA256校验文件和validation-evidence.zip。步骤失败时不发布交付包，在Actions日志中查看具体原因。本流程不依赖Actions大文件Artifact存储，交付文件直接进入Release。

## 交付

Release版本和镜像标签包含运行编号，避免新旧包混用。交付ZIP内有dispatch-image.tar.gz、start.ps1/start.sh、源码和联调记录；只需导入这一个联合镜像。使用说明见[部署文档](../deploy/forecast-dispatch/README.md)。

仓库及Release公开，无需GitHub登录即可下载。提交公司GitLab使用源码；交付ZIP与校验文件单独下载，或通过公司制品库交付，不提交到Git源码目录。部署服务器仍需Docker或兼容的Linux容器运行环境，并按约定补齐真实历史数据。

当前工作流生成Linux/amd64包，不是ARM64包。ARM部署须使用对应架构的基础镜像并另行构建验证。
